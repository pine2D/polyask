## 判读方式

| 标记 | 可以证明什么 | 不能据此推导什么 |
| --- | --- | --- |
| 历史实测 | 指定日期、构建和目标站点的实际开发态/平台结果 | 本轮、现版其它菜单、其它账号或全平台通过 |
| 离线回放 | 生产模块在合成状态机、脱敏 DOM 或模拟网络下的行为 | 真实点击/按键、服务端路由、真实 Drive 或账号可用 |
| 原生合成 | Electron 生产组件在隔离档案、合成页面/数据下的行为 | 真实站点、物理输入法/读屏、其它操作系统或安装体验 |
| 本轮真实验证 | 本轮实际执行且注明版本、平台、站点、用例的结果 | 未执行的能力与环境；本轮目前没有此类站点记录 |
| 待验证 / 受阻 | 缺少目标环境，或该轮未通过、未确认、页面未就绪 | 产品必然故障；也不能用更早的通过覆盖此状态 |

页面可用指页面、输入框及必要 control 的现场证据；不要求 `tier`、`capture` 全绿。切档指生产 `__AMS` 的当次确认，不等于关闭菜单后一定有可读 `state()`。文字/图片列指实际提交，生成列另核对生成信号和完成判定；提交、生成完成与回答归属/采集是三项独立结果。网页上的模型名称仅为观测，不是服务端模型路由证明。

## 选择验收入口

1. 先按改动执行[离线门禁](verify.md#离线回归)及[资源防护](verify.md#断言与测试内存防护)：根目录 `bash scripts/verify.sh`；代码改动在 `desktop/` 经 `npm test` 与 `npm run typecheck`。只改文档不用重跑全部 Electron 测试。
2. 需要原生 UI 时，从[外壳与设置](verify.md#外壳与设置页视觉回归)、[结果库交互](verify.md#结果库视觉与交互回归)、[原图历史与包内主链](verify.md#提问历史原图的隔离原生验收)或[阅读网格](verify.md#2026-11-04-阅读网格与对齐)选择对应专项。Linux 原生入口必须走 `test-safe` 临时 cgroup、隔离合成档案、禁网；合成桥接与包内完整 IPC 分开报告。
3. 适配器/切档/发送变动先满足[开发态真实环境规则](verify.md#真机环境desktop-开发态)，再重启当前源码 `npm start`，在目标视图调用生产 `__AMS`。只读状态同步不打开菜单；切档单独验证点击、复读、收尾和恢复。需要真实发送/上传时，先明确非敏感用例、站点、轮数、图片及账号使用范围，由任务负责人安排；本表不授予发送权限。
4. 完整集成另跑 Linux `npm run package` 与离线包内 smoke，核对最终退出码、共同资源边界、shell=1/sites=9/attached=9 和清理；构建/离线加载不替代真实站点。现版历史门禁见 [1.31.0 发布记录](../CHANGELOG.md#1310---2026-11-04)，2,626 应用项及 546 运行时项是 11-04 的结果，不能写成本轮新增能力通过。

真实文字补验最小记录：目标站点/菜单形态、语言/缩放/视口、唯一合成标记与轮数、页面消息数、submitted 或未确认、生成正向证据、完成/未知、归属/副本对拍和旧副本保持。图片再记批次/张数/格式、就绪、提交后清空及后续纯文字零图；不要将仅上传就绪填作图文端到端通过。取消、迟到确认、同文旧会话等负向分支逐项写实际覆盖，不以离线覆盖替代真机。
